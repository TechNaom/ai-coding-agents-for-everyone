Project Preview: Ship a Real Small Feature With a Coding Agent

This chapter doesn't ship its own project either. Module 1's Level 1 (Guided) project needs the judgment from all three of its chapters — the loop/autonomy model (Chapter 1), prompting and scoping (this chapter), and diff review (Chapter 3) — so it unlocks once Chapter 3 is done.

You now have half of what the L1 project needs: you can write a prompt that gives an agent enough context without drowning it, and scope a task so it's neither trivially small nor dangerously open-ended. That's exactly what "scope the task" will mean when you actually do this for real. What's still missing is the other half — reading and reviewing the diff an agent hands back like a senior engineer would, which is Chapter 3's job. Rather than pad this page with a placeholder exercise, here's what's actually coming.

What the L1 project will ask you to do

The Level 1, Guided project (per the course's curriculum map) has you ship a real small feature using an actual coding agent tool — Claude Code, Cursor, or GitHub Copilot's agent mode, your choice — end to end: scope the task, let the agent run its plan/act/observe loop, and review the resulting diff. You'll submit the diff alongside a short written review log explaining what you checked before approving it and why.

The prompt you write for that project is where this chapter gets tested directly: does it name a specific symptom or goal, does it bound what's in play, and does it give the agent a checkable acceptance criterion? A weak prompt there produces a weak diff to review, no matter how carefully you review it afterward — which is exactly why scoping comes before review in this module's sequence.

Where this fits Module 1 — Using Coding Agents Well: Chapter 1 built the loop/ autonomy mental model, Chapter 2 (this chapter) covers prompting and scoping a task so the agent can actually succeed at it, and Chapter 3 covers reading and reviewing an agent's diff like a senior engineer. The project ships once all three are in place.

Why waiting matters

Shipping the project before Chapter 3 would let you write a well-scoped prompt and then approve whatever the agent hands back without a real review discipline — which defeats the point of a written review log. Finishing the sequence first means the project tests the whole skill, prompting and reviewing together, not just half of it.
