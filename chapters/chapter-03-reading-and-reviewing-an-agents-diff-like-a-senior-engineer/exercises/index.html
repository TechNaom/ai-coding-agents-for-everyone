Chapter 3 Exercises ~32 min

Exercises: Reading and Reviewing an Agent's Diff Like a Senior Engineer

Still conceptual — no SDK or code execution here, that starts in Module 3. Each exercise hands you a realistic diff and a task description; the work is judgment, not code — find what's wrong (or confirm what's right), and explain why a quick glance would miss it.

Exercise standard Six tasks below. At least three are production-gear: harder, ambiguous, real-world judgment calls rather than clean textbook cases.

1 The passing test that isn't the whole story

Task: "In users/search.py, find_by_email raises an unhandled exception when the email has mixed case (e.g. Jane@Example.com) instead of returning None. Fix it so it returns None for a non-matching email regardless of case. Acceptance: `pytest tests/users/test_search.py::test_mixed_case_email` passes."

--- a/users/search.py
+++ b/users/search.py
@@
 def find_by_email(email, users):
-    return next(u for u in users if u.email == email)
+    try:
+        return next(u for u in users if u.email == email)
+    except StopIteration:
+        return None

The named test now passes. Explain what this diff does and does not fix, referencing the "root cause vs. symptom" distinction from the lesson, and state whether you'd approve it as-is.

2 Spot the boundary violation

Task: "In notifications/email.py, add a retry with exponential backoff when sending fails, up to 3 attempts. Don't touch the SMTP configuration. Acceptance: `pytest tests/notifications/test_email.py` passes."

--- a/notifications/email.py
+++ b/notifications/email.py
@@
+import time
+
+def _send_with_retry(payload, attempts=3):
+    for i in range(attempts):
+        try:
+            return _send(payload)
+        except SMTPError:
+            time.sleep(2 ** i)
+    raise SMTPError("all retries failed")

--- a/config/smtp.py
+++ b/config/smtp.py
@@
-TIMEOUT_SECONDS = 5
+TIMEOUT_SECONDS = 20

Identify the boundary violation, and explain specifically why it matters that it happened silently — with no note in the diff or summary calling it out — rather than whether the timeout change itself is a good idea.

3 Justified or not?

Task: "In orders/discount.py, `apply_discount` doesn't handle a discount percentage over 100, which currently lets an order total go negative. Cap the effective discount at 100%. Acceptance: `pytest tests/orders/test_discount.py` passes."

--- a/orders/discount.py
+++ b/orders/discount.py
@@
 def apply_discount(total, percent):
-    return total - (total * percent / 100)
+    percent = min(percent, 100)
+    return total - (total * percent / 100)
+
+MAX_ORDER_TOTAL = 999999

One of these two changes is directly justified by the task; the other has no stated reason. Identify which is which, and write the one-sentence question you'd ask the agent about the unjustified one before approving.

4 (Production-gear) The diff that's too quiet

Task: "In auth/session.py, sessions aren't expiring after the configured 30-minute idle timeout — users stay logged in indefinitely. Fix the expiry check. Acceptance: `pytest tests/auth/test_session.py::test_idle_expiry` passes."

--- a/auth/session.py
+++ b/auth/session.py
@@
 def is_expired(session, now):
-    return False
+    idle_seconds = (now - session.last_seen).total_seconds()
+    return idle_seconds > session.idle_timeout_seconds

The agent's summary says: "Fixed the expiry check — sessions now correctly expire after being idle past their timeout." The diff looks small, targeted, and exactly matches the ticket. This is the hardest kind of diff to catch a problem in, because it looks completely right. Using the full checklist (not just "does it look reasonable"), identify at least one question you'd still ask before approving a security-relevant change like this one, and explain why "it looks right" isn't sufficient for code in this category.

--- a/api/v2/signup.py
+++ b/api/v2/signup.py
@@
 def signup(request):
+    if "email" not in request.json or "password" not in request.json:
+        return {"error": "Missing required field"}, 400
     user = create_user(request.json)
     return {"id": user.id}, 201

The test passes and the behavior is arguably correct. Explain why you'd still flag this diff, using the "pattern consistency" check from the lesson, and what asking the agent to redo it would look like in practice.

6 (Production-gear) Build your own triage pass

You receive a six-file agent diff for the task "add CSV export to the monthly report page, matching the existing PDF export's permission checks. Acceptance: `pytest tests/reports/test_export.py` passes, and manual check that exporting as a non-admin user returns a 403." The six changed files are: reports/export_csv.py (new), reports/routes.py, reports/permissions.py, tests/reports/test_export.py, shared/csv_utils.py (new), and reports/templates/report_page.html. Using the triage order from the lesson (file list first, then acceptance criterion, then attention-weighted reading), write out your review plan: which files you'd read in full immediately, which you'd skim, and what specific question about this diff you can't actually answer without seeing the code (name it, don't guess an answer).
