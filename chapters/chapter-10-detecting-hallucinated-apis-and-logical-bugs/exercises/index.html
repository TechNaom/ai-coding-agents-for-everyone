Chapter 10 Exercises ~45 min

Exercises: Detecting Hallucinated APIs and Logical Bugs

These exercises don't need pandas, requests, or any network access to verify — starter.py and solution.py in this folder test the same three mechanical checks the lesson teaches against small, self-contained stand-ins, so every exercise below is checkable by running the file directly.

Exercise standard Six tasks below. At least three are production-gear: harder, ambiguous, real-world judgment calls rather than clean textbook cases.

1 Implement method_actually_exists

Open starter.py. Fill in TODO 1: given an object and a method name string, return whether that name actually exists on the object AND is callable, using hasattr() and callable(). Run python3 starter.py and get the first four checks to PASS.

2 Implement safe_call

Fill in TODO 2: call a function with the given arguments inside a try/except, returning a structured {"ok": bool, "result"/"error_type"/"error_message": ...} dict instead of letting an exception propagate. Get the next five checks to PASS.

3 Implement has_mutable_default

Fill in TODO 3: use inspect.signature() to check whether any of a function's parameters has a mutable (list, dict, or set) default value. Get the remaining three checks to PASS.

4 (Production-gear) Check a real claim you're unsure about

Without looking it up first, write down whether you believe str.removeprefix is a real method on Python strings, and whether list.sort() accepts a keyword argument called unique. Then use method_actually_exists("", "removeprefix") and method_actually_exists([], "sort") plus inspect.signature(list.sort) to actually check both claims against your real, installed Python. Were either of your guesses wrong, and if so, does the wrong one sound more or less plausible than the real answer?

5 (Production-gear) Trace a boundary case by hand

Given this function:

def last_n_items(items, n):
    """Return the last n items, most recent first."""
    return items[-n:][::-1]

Trace, by hand, what last_n_items([10, 20, 30], 0) actually returns — not what you'd guess, what Python's real slicing semantics produce for items[-0:]. Then run it and confirm. Explain in 2-3 sentences why this specific boundary (n=0) is exactly the kind of case a test suite that only checks "the last 2 of 5 items" would never exercise.

6 (Production-gear) Review a diff for a hallucinated API

A teammate's diff adds this line to a data-cleaning script:

-df = df.drop_duplicates(subset=["email"])
+df = df.drop_duplicates(subset=["email"], keep_highest_confidence=True)

Using method_actually_exists-style reasoning (not a guess), determine whether keep_highest_confidence is a real pandas.DataFrame.drop_duplicates argument. If you don't have pandas installed, reason from the real, documented parameter list you'd check via help(pd.DataFrame.drop_duplicates) or the official docs — not from how plausible the name sounds. Then write a 2-3 sentence review comment, referencing which of Chapter 3's five checklist questions this diff fails and why a green "the script still exits 0" smoke test might not have caught it.
