Project Preview: Ship a Real Small Feature With a Coding Agent

This chapter doesn't ship its own project. Module 1's Level 1 (Guided) project needs the judgment from all three of its chapters first, so it unlocks once Chapter 3 is done.

It wouldn't make sense to hand you a real feature to ship with an agent before you've built the mental model for what the agent is actually doing (this chapter), how to scope a task so it succeeds (Chapter 2), and how to review its diff like a senior engineer would (Chapter 3). Rather than pad this page with a placeholder exercise, here's what's actually coming.

What the L1 project will ask you to do

The Level 1, Guided project (per the course's curriculum map) has you ship a real small feature using an actual coding agent tool — Claude Code, Cursor, or GitHub Copilot's agent mode, your choice — end to end: scope the task, let the agent run its plan/act/observe loop, and review the resulting diff. You'll submit the diff alongside a short written review log explaining what you checked before approving it and why.

Everything in this chapter — telling loop-driven agent work apart from single-shot suggestions — is the foundation that log will lean on: you can't write a credible review log for a change you can't reason about how it was produced.

Where this fits Module 1 — Using Coding Agents Well: Chapter 1 (this chapter) builds the loop/autonomy mental model, Chapter 2 covers prompting and scoping a task so the agent can actually succeed at it, and Chapter 3 covers reading and reviewing an agent's diff like a senior engineer. The project ships once all three are in place.

Why waiting matters

A project that asked you to "just ship something with an agent" right now would teach you to treat the tool as a black box you hope works — exactly the autocomplete-era habit this chapter is trying to break. Building the concept first means the project actually tests judgment, not luck.
