Chapter 7 Practice Bank ~22 min

Practice Bank: Build: A Minimal Coding Agent

Short scenarios, one judgment question each — plus a small runnable script (starter.py / solution.py in this folder) that simulates all four of Chapter 4's directly-testable stop conditions with no live model required. Predict, then run, then work through the scenarios below.

Scenario · First run

The silent hang

A learner runs their own version of this chapter's agent for the first time. It hangs for ten seconds, then prints [step cap reached after 8 steps without a clean stop] with no error. They assume something crashed. What actually happened, mechanically, and what's the first thing you'd have them check in the printed step-by-step trace to diagnose why it never reached a clean stop?

Scenario · Review

The missing safety check

A coworker adds a new tool, append_to_log(path, line), to this chapter's agent, and it passes a quick manual test — appending to a log file inside the workspace works fine. What's the one thing about how it's implemented you'd insist on checking before approving it, regardless of whether the manual test passed?

Scenario · Cost decision

The "just use GPT-4o for everything" pitch

A team lead suggests skipping Ollama entirely and building every learner exercise against a hosted OpenAI model instead, "since it's only a few lines different anyway." What's the real tradeoff being glossed over here, specifically for a course meant to be free and runnable by anyone?

Scenario · Debugging a flaky test call

The tool call that almost worked

While testing an agent against a small local model, you see one run where a tool call's arguments are missing a required key, and the very next identical-input run produces a perfectly formed one. A teammate says "that's a bug in our code, it should be deterministic." Is that the right diagnosis? What would you tell them instead, and what should the code do about it regardless of the answer?

Scenario · Provider swap

The broken swap

Someone swaps this chapter's agent from Ollama to Anthropic's OpenAI-compatible endpoint by changing base_url, api_key, and model as documented, but the system prompt's multi-part instructions stop behaving quite the same way they did before. Given what the lesson's hosted-provider section noted about how Anthropic's compatibility layer handles system messages, what's a plausible, specific explanation — not just "APIs are different"?

Scenario · Scoping a task

The vague task string

A learner passes the task "clean up the workspace" to this chapter's agent with no acceptance criterion. Using Chapter 2's scoping concepts and this chapter's run_shell_command tool specifically, explain what could go wrong that wouldn't go wrong with a task like "delete only files ending in .tmp in the workspace root".

Scenario · Extending the loop

The missing boundary stop

A junior engineer says "we don't need a boundary stop, the system prompt already tells the model not to touch secrets/." Using this chapter's distinction between a prompt instruction and a harness-enforced check like _safe_path, explain why that's not sufficient on its own, and sketch (in words, not code) where a boundary stop would need to sit in dispatch_tool_call.
