Chapter 2 Practice Bank ~20 min

Practice Bank: Prompting and Scoping Tasks for an Agent

Short scenarios, one judgment question each — practice spotting under-scoped, over-scoped, and well-scoped prompts in realistic, sometimes ambiguous situations.

Scenario · Ticket triage

The one-line ticket

A support ticket says only "export button doesn't work." Before typing anything into a coding agent, what two or three pieces of information would you go find first, and why would skipping that step likely produce a plausible-looking wrong fix rather than an obvious failure?

Scenario · Scope creep

The "while you're in there" request

A teammate asks an agent to "update the deprecated date library call in `reports/monthly.py`, and while you're in there feel free to tidy up the rest of the file." The agent comes back having reordered imports, renamed three local variables, and changed a logging format — none of which was the actual ask. Whose scoping choice caused this, and what specific phrase in the prompt made it possible?

Scenario · Overcorrection

The context dump

After getting burned by a vague prompt once, an engineer starts pasting the entire onboarding doc, five past Slack threads, and the whole module's git history into every prompt "just to be safe." What would you tell them about why this isn't actually safer, using this chapter's three-jobs-of-context idea?

Scenario · Boundary-setting

The shared config file

You're scoping a task to add a new environment variable to a service. The config file the agent needs to edit is also read by two other services in the same repo. What boundary clause would you add to the prompt, and what should happen if the agent decides it also needs to touch one of those other services to make the change work?

Scenario · Acceptance criteria

The "make it faster" request

A prompt reads: "This endpoint is slow, make it faster." There's no stated target. The agent adds a cache layer and reports "much faster now." What's missing that would let both the agent and a human actually verify the task succeeded, and how would you rewrite the request to include it?

Scenario · Size judgment

The one-word variable rename

An engineer opens a full agent session, complete with a detailed prompt with context, scope, and acceptance criteria, just to rename one poorly-named local variable in a function they already have open. Every part of the prompt is technically well-formed. What's still wrong with reaching for the agent here, and what would you have done instead?
