Chapter 4 Practice Bank ~18 min

Practice Bank: The Agentic Loop: Plan, Act, Observe, Repeat

Short scenarios, one judgment question each — practice reasoning about the loop's actual mechanism in situations where the human- sounding explanation is tempting but wrong.

Scenario · Folk psychology creeps in

"It got distracted"

A teammate describes a run: "The agent got distracted halfway through and started poking around files that had nothing to do with the task." Looking at the actual transcript, turn 4's tool result was a search hit list that included three unrelated files because the search query was too broad, and turns 5-7 each read one of those unrelated files. Rewrite the teammate's explanation in terms of the actual mechanism, and identify the one thing in the transcript that's the real, fixable cause.

Scenario · Trusting the "done" message

The confident final turn

An agent's last turn is pure text: "All done — the rate limiter now correctly returns 429 on the 6th request." No tool call followed it. Using this chapter's account of what a clean stop actually is (a prediction, not a verified fact), explain what you'd still need to do before treating this task as complete, and why the confident wording of the message itself carries zero evidential weight.

Scenario · Step cap vs. genuine completion

The task that "finished" at exactly the limit

A harness is configured with a 25-step cap. A task's transcript ends at step 25 with the model mid-sentence in a tool call that never gets its result. A reviewer initially assumes the agent finished the task. What in the transcript would tell you this was actually a hard stop rather than a clean stop, and why does that distinction change what you do next (re-run with a higher cap, versus just merging the diff)?

Scenario · A boundary that worked

The tool call that never executed

An agent, mid-task, produces a tool_use block calling run_shell("git push --force"). The harness's log shows the call was intercepted and never executed, and the model's next turn is text asking for explicit confirmation instead. Explain, in terms of this chapter's account of boundaries, why this is evidence the boundary was implemented well — and what it would look like if the same boundary had instead been implemented only as a line in the system prompt.

Scenario · Upfront plan meets a surprise

The checklist that stopped matching reality

An agent using an explicit, visible upfront plan has step 3 read "Add the new field to the API response schema." Two steps later, a tool result reveals the API response is actually generated by a code-generation step from a separate schema file, not hand-written at the response site. The transcript shows the agent editing the response site directly anyway, matching step 3 as originally written. What does this chapter's plan-vs-reactive distinction say went wrong here, and what should ideally have happened to the plan object at that point?

Scenario · Reading a raw transcript for the first time

The junior engineer's first look under the hood

A junior engineer on your team has only ever seen an agent's chat-style summary view, never the raw turn-by-turn data. You show them a transcript with tool_use and tool_result blocks for the first time, and they ask: "wait, so is the summary I normally see something separate the agent writes at the end, or is it just... this?" Using this chapter's terms, answer their question precisely, and explain one thing a reviewer can see in the raw transcript that the chat-style summary view would hide.
